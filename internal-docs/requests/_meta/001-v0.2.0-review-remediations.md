# Part 1 — WO-12: v0.2.0 review remediations (this request)

## TDD references

- §5.2 output constraints (determinism) — dist pruning
- §6.4 / §9.3 player & scoped installs — sandbox enforcement point (**TDD amendment**, see P1-2)

## Context

The pipeline (scan → render → writeDist) is additive-only: nothing ever deletes
from `dist/`. The Tier-2 daemon reads the entire upload body into memory,
inflates zip entries without limits, compares bearer keys with `===`, and
installs packs via rm-then-rename. `homespace.serve.json` (which may hold the
operator key) is not gitignored. Several small correctness nits ride along.

## Scope

- **In scope:** `packages/renderer` (write, offline-budget, escape),
  `packages/serve` (server, keys, zip), `packages/cli` (build), `.gitignore`,
  docs touched by the sandbox/key decisions, TDD amendments required by P1-2.
- **Out of scope / do NOT touch:** contracts §3/§4 (no new manifest fields
  beyond what P1-2 decides), section registry, archetypes, dependency budget
  (§5.4) — everything below is doable with current deps. WO-13+ items stay
  out of this change.

## Likely files / areas

- `packages/renderer/src/write.ts` — writeDist; no pruning exists anywhere
- `packages/cli/src/commands/build.ts`, `packages/serve/src/rebuild.ts` — callers
- `packages/renderer/src/player.ts` — `sandboxTokens()` default
- `packages/serve/src/server.ts` — `readBody`, `installPack`, `serveStatic`,
  upload response body
- `packages/serve/src/zip.ts` — `readZip` inflate limits, CRC, entry count
- `packages/serve/src/keys.ts` — `authorize()` comparison

- `packages/renderer/src/escape.ts` — `escapeAttr`
- `.gitignore` — serve config

## Requirements (acceptance criteria)

### P1 — fix before promoting scoped keys

- [ ] **1. dist/ pruning.** After a build, `dist/` contains exactly the files
      the render emitted (generated files, asset copies, thumbnails) — deleting
      or renaming a pack, section, or theme file leaves no orphans.
      **Ruled: `dist/` is wholly build-owned.** Unknown files are pruned with
      a warning that lists each removed path, and docs give hand-placed
      deploy files (`CNAME`, host config) a supported passthrough via
      `static/` — confirm its copy target reaches the dist root when
      implementing, and make pruning respect it. Mechanism is otherwise
      Claude Code's choice (clean-then-write, or an emitted-files manifest
      diffed against disk — if the latter, it becomes the WO-14 foundation);
      output must stay deterministic (§5.2). Test: build fixture → remove a
      pack → rebuild → assert its detail page, `files/`, and `.thumbs/`
      entries are gone.
- [ ] **2. Scoped-key packs never run same-origin script (ruled).** The
      earlier idea of flipping the §6.4 *default* to `strict` is
      **rescinded**: a strict sandbox has an opaque origin, which breaks
      Godot/Unity web builds (their `.pck`/`.wasm` fetches become
      cross-origin and need CORS headers some static hosts never send) and
      kills save-game `localStorage`. Ruling: operator-authored packs keep
      today's default; packs installed **via a scoped key** get
      `sandbox: "strict"` forced at install time, not overridable by the
      uploader. Where the no-JS direct-open link would still serve such a
      pack's HTML as a same-origin top-level document, use the download link
      instead for those packs (or equivalent — required outcome: no default
      path executes a scoped-key pack same-origin). Amend §6.4/§9.3/§12 to
      document the enforcement point; docs state that manually lifting
      strict on a scoped pack = trusting that system with your origin.
      WO-19 remains the structural fix.

### P2 — daemon hardening

- [ ] **3. Upload limits (ruled).** Request body is **spooled to a temp
      file**, never buffered in RAM; cap configurable with a **1 GiB
      default** (sized for full game builds, not just tmíxʷ posts);
      oversize → `413`. `readZip` inflates with `maxOutputLength` and
      enforces per-entry and total decompressed caps — a zip-bomb fixture
      returns `400`, never OOM.
- [ ] **4. Timing-safe key comparison.** `authorize()` uses
      `crypto.timingSafeEqual` (length-guarded) for operator and scoped keys.
- [ ] **5. Key file hygiene.** `homespace.serve.json` added to `.gitignore`;
      docs recommend `HOMESPACE_OPERATOR_KEY` env var first.
- [ ] **6. Atomic pack install.** `installPack` renames the existing pack
      aside before moving the new one in; on failure the prior pack is
      restored. No window where the pack directory is absent on success paths.

### P3 — small fixes (batch freely)

- [ ] **7. Offline-budget coverage:** patterns also catch `<img srcset>`,
      `<video src>`, `<audio src>`, `<embed src>`, `<object data>`, and CSS
      `@import "…"` without `url()`.
- [ ] **8. Zip integrity:** `readZip` verifies each entry's CRC-32 (table
      already exists) and rejects archives it can't represent (entry count at
      the u16 ceiling / ZIP64 signatures) with a clear error.
- [ ] **9. `escapeAttr` also escapes `'`** (defense-in-depth; all call sites
      currently double-quote).
- [ ] **10. Upload response semantics:** status and body agree — a failed
      rebuild no longer returns `422` with `ok: true`.
- [ ] **11. Malformed percent-encoding** in a request path returns `400`, not
      a `500` from `decodeURIComponent` throwing.
- [ ] **12. Budget-gate scope (ruled).** The gate scans generated text files
      only — `static/` copies and pack-authored HTML (e.g. a game's
      `index.html`) bypass it. **Affirmed as the intended escape hatch**:
      document it in §10.2, and WO-20's doctor later surfaces bypassed files
      as non-fatal warnings. This item is now a documentation task only.

# Part 2 — WO-13…WO-20: upgrade roadmap (summaries)

Outcome-level summaries in TDD §11 style. Each gets its own request file
(002+) with full acceptance criteria when picked up; amendments listed per WO
land with that WO, not before.

### WO-13 — `homespace push` (write-API client)

The §9.2 API has a server and no client. `homespace push <pack-dir> --to <url>`
zips a pack, fills in missing sha256 checksums, and PUTs it with a bearer key
(`HOMESPACE_PUSH_KEY` or `--key`). This is the linked-systems seam: tmíxʷ
publishes story packs to Kwatlp under a scoped key
(`allowedIdPrefix: "tmixw-"`, `allowedTypes: ["post"]`) with one command.
*Amends:* §7 (new command).
*Exit:* fixture pack pushes to an in-process daemon and appears in `dist/`
after rebuild; missing `checksums[entrypoint.download]` auto-added; 401 / 403 /
413 / 422 surface as designer-readable path + problem + fix errors.

### WO-14 — Dist manifest + incremental rebuild

`writeDist` emits a deterministic manifest of every emitted path (+ hash);
pruning diffs against it instead of wiping; the serve watcher maps changed
source paths to affected packs/pages and re-renders only those. This is what
keeps the daemon responsive inside the ~100 GB ops envelope.
*Amends:* §5.2 (manifest is a generated output), §9.1 (watch behavior).
*Exit:* touching one pack rebuilds only that pack's pages plus shared indexes;
incremental output is byte-identical to a full rebuild; manifest deterministic.

### WO-15 — `audio` section + musician archetype

New `audio` section: a playlist of local audio files drawn from selected
packs, rendered with the native `<audio>` element; with JS disabled it
degrades to plain file links. A fifth archetype (`musician`) composes it.
Zero external requests — files ship in `dist/` like every other asset.
**Ruled — album model:** one pack = one album/EP; its media files are the
tracks, ordered by a small `tracks` list in the manifest — keeping music
packs as portable and signable as game packs.
*Amends:* §4 (section registry), §8 (archetypes), §3 (`tracks` field).
*Exit:* section renders and plays from a fixture; no-JS fallback works;
budget gate and a11y baseline (§5.3) pass; archetype builds clean.

### WO-16 — Blog depth (tags, archive, pagination)

`posts` sections gain a page size; the build emits per-tag index pages and a
date archive, linkable from nav. Makes the blog hold up past ~30 entries.
*Amends:* §4 (posts options), §6 (renderer outputs).
*Exit:* a 30-post fixture paginates; `/tags/<tag>/` and `/archive/` exist and
are reachable; `feed.xml` unchanged; output deterministic.

### WO-17 — Static search

Build emits a search index (titles, tags, summaries, post text) plus a search
page with a small inline script — no dependency, no external request. JS off
degrades to browsing; index regeneration can ride WO-14's change tracking.
*Amends:* §4 (search page/section).
*Exit:* fixture queries return expected packs; budget gate passes; page is
usable as progressive enhancement only.

### WO-18 — Pack signatures

Optional detached ed25519 signature over a pack's checksums block, generated
and verified with Node's `crypto` (no new deps). **Ruled — author-level:**
pack *authors* sign their packs, so provenance travels when a pack moves
between homespaces; operator countersigning can layer on later. `homespace
verify` extends `--verify` to check signatures when the author's public key
is configured. A real trust
story for downloads with zero infrastructure.
*Amends:* §3 (optional signature field), §7 (verify).
*Exit:* signed fixture verifies; tampered file or signature fails with a clear
message; unsigned packs are unaffected.

### WO-19 — Cross-origin pack serving (design-first)

Daemon option to serve `packs/*/files/**` from a second port so pack-authored
HTML is cross-origin to the shell — making WO-12's same-origin concern moot by
architecture. Docs describe the equivalent `packs.` subdomain pattern for
static hosts. Design wrinkle to resolve first: the renderer must emit
absolute pack-asset URLs when configured, and §10.2 needs a
"configured self-origins are not external" allowance.
*Amends:* §6 (asset URL config), §9.1, §10.2.
*Exit:* with the option on, player iframes and direct links use the pack
origin; shell pages stay on the main origin; budget gate passes with the
allowance; daemon serves both ports.

### WO-20 — `homespace doctor`

One command that checks a built homespace end to end: internal link and asset
404s, image alt coverage, checksum `--verify`, and a budget scan extended to
the *whole* `dist/` — including `static/` copies and pack HTML — reported as
warnings, honoring whatever WO-12 item 12 decided about the escape hatch.
*Amends:* §7 (new command).
*Exit:* fixtures with a broken link / missing alt / tampered checksum each
report path + problem + fix; a clean homespace exits 0.
