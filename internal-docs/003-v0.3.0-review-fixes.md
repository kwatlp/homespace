## Context

The gates (`tsc --build`, vitest, bundle freshness) exist but only run when
someone remembers. `docs/static/builder/` is committed build output with no
freshness guard. The wizard's single `build` slot only feeds **game** packs —
apps silently get the placeholder, against the ruled "plug in assets for
each field." Plugged gallery images ship `alt="Picture N"` because nothing
collects descriptions. And the page loads via
`<script type="module">`, which browsers refuse from `file://` — so the
"download it and double-click" story quietly breaks.

## Scope

- **In scope:** `.github/workflows/`, `packages/builder` (wizard, ui, page,
  bundle script), the renderer head/link emission only as far as item 7
  requires, docs touched by items 3 and 8.
- **Out of scope / do NOT touch:** folder-picker upload for subdirectory
  builds (future WO), WO-13+ roadmap items, contracts §3/§4 beyond what
  item 7 needs, the serve daemon.

## Requirements (acceptance criteria)

### P1 — the guard rail

- [ ] **1. CI workflow.** `.github/workflows/ci.yml` on push + PR: Node 20,
      `npm ci`, `tsc --build`, `vitest run`, then rebundle
      (`node packages/builder/scripts/bundle.mjs`) and
      `git diff --exit-code docs/static/builder` so committed artifacts can
      never drift from their sources. AC: workflow is green on this PR;
      editing page source without rebundling makes the diff step fail
      (demonstrated locally in the PR description).

### P2 — ruled-AC gaps

- [ ] **2. Apps get their own build slot.** Separate plugged-build state and
      file inputs per kind (game / app), each flat multi-select with the
      existing `index.html` check. Plugging into either lands in that pack;
      plugging into both works at once; wizard tests cover each path.
- [ ] **3. Alt text is collected.** After gallery images are chosen, the
      wizard shows one short description field per image; entered text lands
      in the pack's `media.alt` map, blank keeps today's fallback, and
      `START-HERE.md` teaches editing alts later. AC: a11y baseline (§5.3)
      pass on a wizard-produced site with described images.
- [ ] **4. The Builder runs from a double-click.** Bundle the page as a
      classic script (esbuild `iife`) or equivalent so
      `docs/static/builder/index.html` works from `file://` — module scripts
      are CORS-blocked there today. AC: opening the file from disk runs the
      full wizard in Chromium and Firefox; the served path is unchanged; the
      freshness gate covers the new artifact shape.
- [ ] **9. Docs auto-deploy (ruled).** On every merge to `main`, CI builds
      the docs homespace (`npx homespace build` in `docs/`) and publishes
      its `dist/` to GitHub Pages — the Builder gets a permanent public
      address that can never drift from the repo. AC: the Builder loads and
      completes a full wizard run at the Pages URL; every internal link
      survives the project-subpath (`/homespace/`) — verify the renderer's
      relative URLs hold there and fix any that don't; README and the setup
      instructions gain the real address, replacing the placeholder.

### P3 — polish

- [ ] **5. Slug field mirrors state.** The input shows the slugified value
      the state actually holds, so the download filename never surprises.
- [ ] **6. Un-pick an icon or banner.** A "use the placeholder instead"
      control clears a chosen asset; cancelling a re-pick keeps the prior
      choice.
- [ ] **7. Icons keep their format.** An uploaded icon is written with its
      real extension and the page links it with the matching `type`, instead
      of any bytes being named `favicon.ico`. Mechanism open; outcome fixed.
- [ ] **8. Flat-build limit is visible.** A hint under each build input says
      flat files only — no subfolders; foldered exports (Unity-style) go in
      via the master copy — and the docs say the same.
